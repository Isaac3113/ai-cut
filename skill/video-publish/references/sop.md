# 剪辑完成后的归档与发布 SOP

此流程只接收已完成的剪辑交付。它不会后台监听文件夹，也不会在每次导出后自行发帖；由用户本次任务或已确认的制作流程进入。`ai-cut` 管剪辑，`video-publish` 管归档与发布，`fb-content` 管 Facebook 写作。各 Skill 的职责和账号授权分开。

## 一、接手资料和个人配置

先对齐作品编号、完整标题、本版 revision，以及用户已经确认的内容。找到原片、选定真实导出 MP4、16:9 和 9:16 两封面、本版现有 TXT／SRT、已有 Drive 文件夹及 Marketing OS 内容 ID。编辑器显示完成或下载按钮出现，不证明本机 MP4 已保存；读取实际文件并检查可播放、时长、画幅、大小。缺原片等单项时可继续准备已具备的资料，但不能称四份媒体归档完成。未完成的完整观看／听审等仍标待验证，不因用户说满意就补填技术通过。

个人配置是用户资料，保存在公开源码之外。读取顺序为本次指定路径、环境变量 `VIDEO_PUBLISH_PROFILE`、本项目可选的个人 OneDrive 路径；不在公开包里填私人 ID。当前默认约定用当前用户目录解析，不硬编码 `C:\Users\User`。其他电脑或 OneDrive 企业路径不同，使用明确配置路径，不创建猜测的目录。

| 配置项 | 内容与使用方式 |
|---|---|
| `schema_version` | 当前配置版本；此 SOP 使用 `1` |
| `owner_name`、`timezone` | 负责人显示名与时区，例如 `Asia/Kuala_Lumpur`；日期按此解释 |
| `drive.parent_folder_id`、`drive.parent_folder_url` | 用户选定的 Drive 父文件夹；真实回读核对，不能把 Marketing OS 地址当 Drive 目录 |
| `marketing_os.base_url`、`marketing_os.workspace_name` | 用户选择的 App 和工作区；连接状态每次核对 |
| `accounts[]` | 每项含 `platform`、`display_name`，可加已核对 `id` 与 `aliases`；别名用于识别，不扩大账号范围 |
| `first_comment_text` | 最新确认的整段首评；它是唯一首评原文来源，不拼接历史版本 |
| `fixed_hashtags[]`、`copy.minimum_hashtags` | 本人的固定标签和至少数量；本项目所有者已确认为五个固定、每平台至少十个，其他创作者按自己的已确认方案 |
| `copy.facebook_skill` | `fb-content`；找不到时不能自己冒充已调用 |
| `copy.facebook_instagram_mode` | 已确认的 `shared` 或 `independent`；不擅自改文案模式 |
| `defaults.owner`、`defaults.internal_status` | 准备阶段常用负责人和内部状态；按实时选项核对 |
| `defaults.preferred_production_type`、`defaults.audiences` | 制作类型和客户群的候选提示；按本片实际来源和主题选择，不是每片必填相同值 |
| `defaults.content_strategy` | 常用策略提示；本片适用才采用，不机械套用 |
| `local.work_root`、`local.delivery_root` | 私人运行记录与媒体交付根，不能用 Drive 或公开 Git 替代 |

缺少某个非当前阶段必需的项不阻塞全部工作。未配置其他创作者的账号时，询问他自己的目的地，不能默认使用讲师的账号、固定 DA 或长期授权。品牌／offer 不同，按 `fb-content` 的 DA 选择合同处理，不能硬接 AGI TOP 尾段。

## 二、先处理 Google Drive

1. **定位父文件夹。** 优先使用已连接的 Drive 工具，读取目标文件夹名称、ID、所属账号和已有子项。用户先前明确选过本条父目录就沿用，不反复问。共享权限保持原样，上传不等于授权公开整份原片。
2. **搜索并复用作品文件夹。** 用正式完整标题在该父目录内查找；命中同片则核对记录后沿用，不因再次执行而创建同名副本。没有才在该父目录创建与视频正式标题相同的文件夹。编号和标题沿制作项目，不能凭日期另编号。
3. **核对四份媒体。** 原片一份、当前成片一份、16:9 封面一份、9:16 封面一份。不放文案、ZIP、检查证据、工程或缓存。既有文件夹有其他用户文件时不自动删除；指出与期望清单的差异。
4. **先比对再上传。** 记录本机绝对路径、文件名、字节数、哈希和类型；与云端 ID／大小／校验值核对，相同文件复用。不同内容同名时先判断是用户已授权的同片更新还是冲突，不盲目覆盖或累积旧成片。
5. **走当前支持的上传通道。** 先读工具实际合同与限制，不能把某次接口的大小上限当所有上传方式的永久规则。连接器不支持大文件时，使用用户已选择且已授权的 Drive 官方网页及正常文件选择器；优先 Codex 右侧浏览器。没有本机文件权限时说明具体所需设置；不要循环失败、要求用户重复已完成的授权，或将大文件传到陌生中转服务。
6. **等待并回读。** 原生文件选择成功、出现上传进度都不是完成。等上传结束，再列目录，核对四份实际文件 ID、父目录、类型和大小；能读到校验值时比对。保存 Drive 文件夹及成片 URL 到私人工作记录。

## 三、Marketing OS 内容入库与媒体关联

1. 打开配置的 App，确认正确工作区、Google 账号与内容管理入口。先按作品编号／标题搜索已有内容，复用同片记录；找不到才创建。不要在其他系统另起一份平行内容。
2. 在 Google Drive 连接处检查实际账号状态。**账号已连接、Picker 能打开、具体 Drive 文件 ID 已关联、视频能播放，是四个不同结果。** 不能由“已连接”推断后三项。
3. 优先在选片界面关联刚验证的 Drive 成片 ID，独立选用获认可的平台封面。上传两张封面不等于两个视频；视频仍沿本条确认比例。旧自动截帧如仍是参考，不把它误选成正式封面。
4. 若 Drive Picker 空白或关联失败，保存真实错误与阶段；有本次素材上传授权时，可以用已存储的真实成片 MP4 和封面作为发布素材，同时在内容资料中保留 Drive 文件夹／成片链接。明确报告“Google 账号已连接，单文件关联未完成，当前使用已上传素材”，不能宣称已实现 Drive 自动同步。没有对应上传授权则只停该步。
5. 填正式内容名称与标题；制作类型按实际来源选择，内部状态准备阶段一般为待审核，负责人、内容策略、客户群按本片和当前选项填写。例如教育主题可以是知识分享／教育受众，但其他行业不能继承这个案例。广告投放方式、广告预算与广告账号不在本流程。
6. 保存并重新打开内容，检查实际视频／封面、标题、制作类型、状态、负责人、策略、受众及 Drive 关联结果。保留真实内容 ID 和可打开入口。

## 四、文案、标签与首评

### Facebook 与 Instagram

读取并实际调用已安装的 `fb-content`。用本版字幕／转写和必要画面理解对象、实际演示的方法与条件；已认可正文保持原样，不能因重传或重新打开而再写一版。

新写／获准改写时，按该 Skill 当前合同：Attention + **Demand** + Description + Action；默认新写上半 AD，原样追加已锁定 DA，不用旧 AIDA。上半每三个自然段成组、组内单换行、组间空一行；DA 大小写、标点、换行与顺序都不润色。用具体老板场景、自然大马中文和工作英文，不写功能说明书，不编客户原话、业绩数字、免费优惠或效果保证。用该 Skill 的拼接脚本锁住 DA，核对实际保存文本。

本条已设置 FB＋IG 共用并获认可时沿用，共用稿要适合两边真实字符上限；不能为塞进 IG 自动缩掉固定 DA。确有冲突先给用户看适配方案。平台独立模式时只改授权的平台。正文与标签在 App 分字段时分别填，不在两处重复放同一套 hashtag。

### TikTok 与标签

TikTok 使用适合视频的一条独立短稿；保留已认可版本。检查当前 App／渠道实际字符限制，不把某次界面的 `150` 当所有 TikTok 的永久通用限制。不要把 FB 固定长 DA 整段塞过去。

按本人配置的最低数量与固定项准备标签。本项目所有者已确认各平台至少 10 个不同 hashtag，含配置的五个固定标签；这不是其他创作者自动继承的营销要求。其余从视频实际内容与 Google 搜索到的相关词选择，记录查询、日期、来源与对应关系；没有真实搜索就写未核对，不编搜索量或排名。平台硬限制与用户要求冲突时，说明具体平台、限制和建议，请用户选择；不要把多出的 hashtag 塞进固定首评。

### 首条留言

从个人配置读取最新确认的 `first_comment_text`，逐字填入每个目标账号的首评字段。在支持的界面可用“留言用于所有已选账号”，然后逐账号切换回读。当前这位用户已选定的三个链接用途是系统快速介绍、解决企业问题、学员见证；实际 URL 和文案以个人配置为准，不用旧免费报名或旧见证地址补位。

首评里不放音乐许可、来源、正文 CTA 或其他附加文字。不要删除私人制作来源／许可记录，也不要把私人存档称为满足必须公开署名的要求；若素材许可确需公开署名而尚无合法安排，处理该具体素材问题后再发布，不能用“已删尾注”冒充解决。

平台／工具不支持或不能保存首评时说明具体限制，不把首评挪进正文，也不擅自绕道另发公开评论。视频发布成功与首评实际出现分别验证。

## 五、账号、选项、时间与保存草稿

1. 在“发布设置／自动发布”打开本条内容。依据配置和已确认目标逐一选择账号，把实时显示名、平台、ID 与用户别名对应起来；重名或 ID 对不上时先查，不猜选。范围是配置的 FB／IG／TikTok，排除未授权 YouTube 和其他账号。
2. 核对每个平台真实模式：FB Feed／Reel、IG Reel 等沿已确认设置和当前支持项，不靠标题推断。视频封面开关选中后检查预览确实显示获认可封面。TikTok 可见范围、评论开关和商业内容声明按实际内容及现有确认填写，不随手关掉已确认选项。
3. 按本次要求设置发布时机。用户明确“立即发布”就选立即；“只放草稿”不得提交；“明天十点”先按配置时区换成明确日期。没有明确时刻而用户授权选当天时间时，先看账号自己的受众数据，缺少才采用可查行业资料作测试建议。不要把某次 `20:30` 写成通用最高流量时段。
4. 对未来定时，提交前查当前时间和时区，确保仍在未来。审阅等到时刻已过时，重新安排并请用户确认，不能静默改立即发布。发布时机的当前明确指令可以替代旧草稿时间，不要求用户重复相同授权。
5. 点击“保存草稿”，等保存流程结束。旧的成功提示可能仍与“正在核对账号／素材”同时出现，须等本轮保存完成，再关闭／刷新／重新打开，核对实际记录。
6. 逐账号回读：完整正文、标签及数量、最新首评、媒体和封面、目标账号、渠道、时间与时区、状态。记录每个账号草稿 ID 与入口。出现“有未保存设置”不能交付为已保存；看到旧“等待同步”提示先查属于哪个内容，不为本条去同步其他记录。

## 六、给用户看清楚，再按明确授权提交

给出当前视频、16:9／9:16 实际封面、可复制的平台文案、首评、账号与发布方式。已有明确认可只记录，不重复问。没有本条发布授权时停在已保存的可审阅草稿；用户只认可视频或封面，不代表他认可全部文案与首评。

用户对这版明确说“发布／post／立即发布”后，在该版、该账号、该时机范围内提交一次，不再另加相同的确认环节。若需要实质改动正文、媒体、账号或首评，先完成新的可审阅稿再取得相应确认。Skill 自动选中不构成长期发布许可。

提交前保存一份私人工作记录：作品 ID、revision、媒体哈希、正文／标签／首评哈希、账号 ID、立即或具体定时时刻、授权范围和时间、已有草稿／请求／帖子 ID。公开仓库不保存这份记录。

在当前 UI 点击对应“立即发布到 N 个账号”或“确认排程”。按钮文字可能随版本改变，依据实时页面确认动作含义；不要用“保存草稿”代替提交，也不要在过程中重复点击提交。

## 七、逐账号核对与防止重复发布

| 实际状态 | 可以怎样说 | 接下来做什么 |
|---|---|---|
| 草稿保存成功 | 已存草稿，尚未提交 | 等用户发布指令 |
| 已提交／accepted／Pending／处理中 | 已交平台处理，尚未确认公开 | 用状态同步／发布历史查同一请求，保存 ID |
| 已排程 | 平台已接受指定时间 | 回读账号、时刻和时区；不称已公开 |
| 平台明确已发布且有匹配帖子 ID／链接 | 该账号已发布 | 打开实际帖子核对视频、封面、正文；首评另查 |
| 明确失败且确认没有创建帖子 | 该账号失败 | 说明原因，只处理该账号；有重复风险时先查历史 |
| 超时、连接中断、结果待核实 | 该账号结果待核实 | **先停重试**，按已存请求／帖子 ID 同步或查历史，不能重发整组 |

部分成功时维护账号级结果：已成功的保留原帖子 ID，不为失败账号再次点击五账号总提交。查询只读取当前条目的结果／历史，不能把“列表没立刻出现”当确定没创建。确认原动作确实没有创建、且重试仍在本条授权范围内，才针对那个失败账号执行；目标或内容改变需要新确认。工具不能按单账号安全恢复时，报告具体限制，不用整组重发凑完成。

发布后持续在当前任务内核对到可确认的结果。首评可能晚于视频出现，单独检查实际状态；工具只返回预设首评不证明平台已发出。没有可取得的最终状态或外部访问权限，明确保留“已提交，待核对”，提供已知 ID／入口和所需下一步，不伪造完成或无限刷新。

## 八、交付与复用

向用户报告：

- Drive 文件夹与四份媒体是否验证；Google 账号连接、Drive 文件关联是否真实完成。
- Marketing OS 内容入口、实际保存资料、每个目标账号的草稿／排程／发布／失败／待核实状态。
- 已取得的帖子链接、首评状态与必要截图。截图保存到工作区，实际嵌入答复。
- 尚未完成或受限制的具体一项；不能把系统接受、用户认可、媒体检查和平台公开混为一件事。

SOP 与 Skill 只保存当前已确认的稳定做法。个案的错误旧文案、两链接首评、固定测试时间、一次上传上限或临时按钮路径，不写成未来默认。工作记录留实际环境；换电脑用 Git 同步规则、OneDrive／配置同步个人资料，账号登录与权限需要独立核对，不因 clone 便声称全部能用。
