发布素材打包规则：0.2.7（2026-09-15，保持）。剪辑交互规则新增0.2.8：

**小红书视频同样必须先问视频比例，收到本条明确回答后才开始剪辑；默认原始视频直接1.2倍一次。** 详细提问、用户答复记录与核对见[user-preferences](user-preferences.md)。只写小红书、9:16/4:3封面需求均不能代替视频比例确认。文案与封面制作任务本身不触发重新询问已经确认的视频比例。

用户已认可额外的4:3横版小红书封面，要求以后每条完整口播保留原有封面并增加这个比例：Facebook文案/封面、小红书文案/竖版封面/4:3横版封面，共五项。4:3横版是该用户的交付偏好，不称为小红书统一强制标准。此更新不改渲染引擎0.2.5、原声、绝对1.2倍或唯一主时间轴。

## 范围与阅读顺序

总 Skill → final-delivery → 本页 → cover-prompt-worker → 可用的 imagegen。先读本条品牌资料、最终正文 TXT、已认可的封面风格和用户新提供的参考资料；不把旧案例标题、促销、任务数据或本人图片自动套到其他创作者。

若安装了 facebook-copywriter、xiaohongshu-copywriter 和 image-prompt-designer，可按下述步骤调用；个人插件不属于必装依赖，没有时当前 Codex 直接执行本页与 cover-prompt-worker。辅助 Skill 的默认 ADDA、20篇批量、只输出提示词等规定不能覆盖本条的一篇 AIDA Facebook、一篇小红书及真实图片交付要求。不为此安装商业服务、购买模型 API 或自动发帖。

## 每条完整片按顺序做

1. **锁定口播依据。** 复用当前主时间轴导出的最终无时间轴 TXT，核对品牌、名字、数字、否定、条件、功能范围和原片中的行动指引。记录 TXT 哈希与本版视频绑定。营销文案是据此改写的附加文件，不改动字幕 TXT/SRT，也不把封面文案混入原声字幕。
2. **选一个主重点。** 明确本条对象、遇到的具体问题、视频实际展示的方法及下一步动作。优先读用户参考，网上只借结构和写法，不复制正文、不从热度推断转化。用户要求搜索或涉及当前平台规则时查最新来源、保存 URL/日期；其余可沿用已认可的写法，不每片无意义重搜。无法核实的规则不写成平台硬要求。
3. **写 Facebook 一篇。** 内部按 AIDA 检查：Attention 用人物处境或具体结果开场；Interest 描写实际烦恼和为什么值得继续看；Desire 用视频支持的操作过程解释带来的好处；Action 给一个明确下一步。不要在成品打印 AIDA、Attention、Interest、Desire、Action、框架说明、来源注释或“以下是文案”。
4. **写小红书一篇。** 用短、具体的标题明确对象与问题；前几行直接进入场景；正文给可操作步骤、检查清单或条件清楚的前后对照；结尾用一个与内容相关的问题或站内行动自然收尾，再加少量相关标签。不要把 Facebook 换个平台名就当小红书笔记，也不用“姐妹们/家人们”硬套老板教学内容。
5. **主员工审文案。** 逐项对照第1步：每个产品功能、案例、数据和承诺有何依据；比喻/假设例子须能看出是例子，不伪装真实客户经历。检查 AIDA 四层是否成立、小红书标题承诺是否被正文兑现、两篇是否自然白话。缺分享会日期/价格/链接时不编造，采用已有口播支持且不依赖缺失信息的下一步。未经证据不写保证业绩提升、轻松赚钱、排名、稀缺名额、倒计时、免费优惠或用户好评。“爆款风格”不是效果保证。
6. **排成可复制正文。** 每个简短语义段在输入 TXT 占一行，连续三小段后空一行；最后不足三段自然结束。不是每三字/每三句硬切，不拆掉条件或语义。Facebook 文件只有可发正文；小红书文件可含实际发布标题、正文步骤与标签。聊天中分别用两个 text 代码块，框外注明平台，让用户用代码块复制按钮一次复制，不把编号、解释、来源或提示词塞进去。文件提供同内容纯 TXT 与双代码块 Markdown。
7. **按三个输出画幅准备封面结构。** 用最终口播 TXT + 对应平台文案 + 同一真实人物帧/已认可本人封面 + 品牌 Logo 配色，分别调用 cover-prompt-worker。每平台先给四个不同角度标题，主员工选定一个并审阅执行 Prompt；小红书竖/横版可共用已选标题与本人参考，但分别写构图，不必重复选题。封面只抓一个重点，与正文一致，标题短、手机缩图清楚，有能解释主题的画面；不用密集 UI、满屏小字、塑料立体字或赛博装饰。
8. **分别真实生图并看图。** Facebook 延续该用户已认可的布局与比例（当前教学视频为约16:9），不能因通用 Feed 建议擅自替换。小红书保留已确定竖版，默认接近3:4，如1242×1660；若用户已指定9:16则沿用。除此之外每次还须单独生成4:3横版，如1448×1086或1600×1200，宽大于高。竖横版分别排人物、标题和主题对象，不将3:4写反为4:3，也不拉伸或硬裁原封面。人物身份、脸、眼镜、服装、手部须自然一致；用 Logo 青蓝为主色，标题用深色与青蓝区分重点，画面需要的完成勾可用绿色。内置 imagegen 前实际看参考图，生成后看中文、脸/手、构图、安全边距和缩图可读性；有错误做针对性修正。记录实际尺寸、工具返回文件、参考来源、原稿及执行 Prompt、检查结果。工具未返回具体模型版本时不称“最新最强模型已验证”。
9. **保持片内封面与平台封面边界。** 默认仅将适合视频原比例的封面放入既有主时间轴。三张社媒封面不代表要导出三支视频，也不将小红书3:4图片直接拉伸塞进16:9片头。用户已认可的 Facebook 封面可原样复用；只制作附加文案/小红书图不重剪已认可视频。插入片内封面后按 final-delivery 重新冻结字幕，若口播语义变化，返回第1步复核两平台内容。
10. **一次整理五项并校验。** 使用源码 scripts/package_social_delivery.py 整理到同条视频的 `05_成片/最新版/发布素材`，与 MP4、TXT/SRT、完整制作说明一起交付；运行 audit 校验文件、图像、排版和本版绑定。缺任一文案或图，尤其新增4:3横版，不能称五项完成；图工具失败时保留其余完成项及提示词，明确缺图，不拿文字结构稿冒充图片。

## 超级白话的写法

- 每句话让读者看到动作、场景或变化。不要只写“提升效率、系统很强、改善管理”。例如“打开看板，查看谁的任务今天到期、客户收到什么回复”，前提是视频确实支持这些能力。
- 面向该创作者的大马华人老板受众，中文为主，自然使用 sales、follow up、dashboard 等原片里已有常用词。不硬塞方言或装腔，不把每句都写成营销口号。
- 可以把“记得跟一下”改成明确的任务示例，但标明“例如”，不能说这是用户真实客户的对话或已实现的效果。
- 用户资料《FB 文案写法知识》讲 ADDA；学习其对象、场景、购买理由、功能到结果、清晰行动写法。本用户当前明确选择 AIDA，内部按 AIDA，发布正文不标框架。
- 用户资料《把幸福快乐换成超级白话》里的数字、医疗/收入效果只是教学例句；不得继承到产品事实。没有量化依据就写具体操作与可观察变化。
- 小红书用知识分享的节奏：问题 → 可执行步骤 → 小清单 → 自然互动。标题不夸大、内容不空心；标签贴主题，不堆无关热门词。

## 文件与工具

```text
05_成片/最新版/
  原有MP4、口播TXT/SRT、完整制作说明及工程资料
  发布素材/
    Facebook/文案.txt
    Facebook/封面.png 或 .jpg
    小红书/文案.txt
    小红书/封面.png 或 .jpg     既有竖版（3:4或用户指定9:16）
    小红书/封面_4比3横版.png 或 .jpg
    一键复制.md
    交付清单.json
    制作依据.md                 原稿/执行Prompt、来源、实际审阅记录
```

在已有源码环境运行（路径自行换成本条真实文件）：

```text
python scripts/package_social_delivery.py build --transcript 最终口播.txt --video 最新成片.mp4 --facebook-copy fb.txt --facebook-cover fb.png --facebook-ratio 16:9 --xiaohongshu-copy xhs.txt --xiaohongshu-cover xhs.png --xiaohongshu-ratio 3:4 --xiaohongshu-landscape-cover xhs-4x3.png --evidence 制作依据.md --out NEW_发布素材目录
python scripts/package_social_delivery.py audit --out 发布素材目录 --transcript 最终口播.txt --video 最新成片.mp4
```

新建包使用schema_version=2 / workflow_rules=0.2.7，必须提供额外横图。旧schema 1包不静默算新规则齐全：仅核对历史时显式用audit --allow-legacy，结果current_workflow_complete=false；升级时先复用原文案、竖版和Facebook图片，补真实4:3图再build新包，不手填空文件或只改版本号。9:16竖版传--xiaohongshu-ratio 9:16。

输入文案非空行作为小段；工具只排版，不改写观点。建包先验证所有输入，拒绝覆盖现有目录。后续修改先在本机工作区新目录验证，按原项目最新版规则保护旧记录后替换受影响文件，不并列堆多版。只调音乐且 TXT 未变化，可复用两篇文案和图片，重新绑定最新 MP4；只改一个平台文案/图片，不重新做另一个平台或 ASR。

检查器能证明文件齐全、能读图、画幅匹配、三段分组、复制块正文一致以及哈希没变；不能证明文案事实、AIDA说服力、本人相似度、图中文字准确或传播效果。这些由主员工真实阅读/看图并写制作依据；未做的如实标未验证。视频原有全片试听/观看未完成项不得因发布素材齐全而自动通过。
