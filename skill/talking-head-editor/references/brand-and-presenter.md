# 品牌配色、淡Logo、绝对1.2倍与动态口播圆窗

本章是0.2.5的新默认，覆盖旧固定黄/奶油配色、默认1.1和可选人物小窗。既有原片、删改、声音、交付、共享存放和真实验收规则继续有效。

## 1. 从Logo建立可执行的品牌约束

读取用户提供的Logo文件并实际查看透明边缘、颜色、背景和辨识度。记录路径、SHA256、透明范围、主色/辅助色，以及为文字可读性派生的深字与浅底；派生色不能冒称直接取自Logo。保留Logo原比例，不擅自重绘商标。Logo缺失时标`pending_logo`，继续粗剪等独立工作，但不编造品牌色或声称完整品牌交付。

Logo作为独立可调整水印层覆盖成片，透明度先用8%～12%，根据深浅背景、手机预览和原Logo对比度调到隐约可见。不得为了可见而遮住脸、字幕、卡片状态或主要动作。超出此范围时记录真实对比度原因；不能把参数设置成功当作看过成片。

品牌主/辅色必须进入：重点字、流程卡、箭头/计时/状态、封面、片尾。常规字幕、细小文字及警示色可使用明确记录的可读性中性色/功能色。旧模板的黄色不要漏留在新动画、既有关键词props、封面生成Prompt或结尾组件。图片封面Prompt也要带品牌主色和派生色，生成后实际检查；生图出现相近颜色可记录近似，不伪称精确色值。

## 2. 相对原片绝对1.2倍，只实施一次

新任务`default_plan`从0.2.5默认1.2。旧plan已保存的速度不被静默改写；本次要求重剪时按revision/官方时间轴变更，用原片源范围重新计算。旧缺字段计划继续按1倍解析以兼容历史。

ChatCut中把所有原声配对的真人段设为1.2，按同一主时间轴重算视频、人声、字幕、素材锚点、PIP、重点字、SFX、封面与片尾位置。不能把旧1.1成片再乘1.2变成1.32，也不能反复加速。BGM保持自然速度；新动画按最终帧重渲染，在主轨1.0倍插入。以实际源范围÷输出时长检查速度，允许整数帧量化误差。

`scripts/audit_visual_contract.py retime INPUT --out NEW_JSON --start-frame 30`提供源范围推导的提案，重复运行绝对1.2结果相同；它不是自动改动ChatCut。原声源范围不能从已经混合的旧MP4伪造。

## 3. 全屏素材时真人动态圆窗必须在场

每段取代主画面的B-roll、流程、界面演示或全屏动画，只要正在讲原声，就持续显示同一段原片、同一源时码的动态真人圆窗。普通真人画面上的重点字和轻推近不重复添加圆窗。无口播封面/静态片尾按自身版式处理，不硬放一个无关动态人物。

先在同一时间轴与全屏素材范围求交集，再按真人原声剪切点拆圆窗；不能拿另一段本人讲话、循环片段或静态头像代替。圆窗起止源时码、速度和原声一致。复制层显式静音，唯一原声在A1；检查`audioDetached`/muted，避免视频层重复声音。

优先左下或右下，尺寸以能看清口型且不抢主体为准。先预留字幕安全区，再裁成真正圆形，源画面不得拉伸。跨场景如需换角，依据避让条件/状态/对象的需求平稳切换。遮挡时改圆窗位置/大小或改动画构图，不删掉强制圆窗。ChatCut可用能力以当次工具和实际像素为准：预设报不存在就使用已验证的圆形遮罩/布局能力；圆角矩形不是圆形。任何本轮未实现的圆形功能须明确说明，不用字段冒充。

`scripts/audit_visual_contract.py plan-pip INPUT --out NEW_JSON`把现有最终原声段和全屏素材范围自动求交，生成同源动态圆窗的准确切片提案。编辑器实际执行后，重新从官方完整快照和inspect结果填入审计文件，逐段查覆盖、资产、源时码、静音、形状、边界和字幕碰撞。规划提案本身不能当实际执行证据。

本机旧renderer的`overlay.mode=pip`是把补充素材放小窗，不是把真人持续放圆窗；不把这个字段当新规则已自动实现。当前采用ChatCut能力执行真人圆窗；其他路线必须补上真实合成与渲染验证后才声称支持。主plan_schema仍为1，不新增渲染器忽略的品牌/PIP字段。

## 4. 增加画面解释，而不是多塞大字

逐句检查需要观众“看见”的机制：任务交给谁、完成/未完成、多久没回、复制给多个销售员、等待后发消息、老板打开记录、费用和跟进责任的对比。适合时补对象动作、实拍、界面示意或信息对比；记录原话、对象、动作、条件、结果及起止帧。

短状态变化可用HyperFrames，连贯多步/计时用Remotion，短关键词用ChatCut原生MG。不要只保留固定三处长流程；也不规定必须调用某引擎多少次。增加动作必须相关、可读、不捏造功能，模拟界面标“流程示意”。每3～5秒可见变化和5秒间隔上限仍适用，普通字幕换行不算设计事件；别为凑数抖动或每次响SFX。

## 5. 冻结证据的实际审计

新增独立`scripts/audit_visual_contract.py audit INPUT --out NEW_REPORT`。输入格式是`schemas/visual-contract.schema.json`，不是本机编辑plan；保留原始官方快照/inspect回答，归一化后输入下列字段：

- `evidence_sources`: 原始官方快照/inspect证据的`path,sha256`数组，至少一份且实际哈希匹配；未绑定就pending，不把计划当完成。
- `schema_version: 1`、`fps`、`duration_frames`、`canvas:{width,height}`。
- `speech_segments`: `id,asset_id,from_frame,to_frame,source_start,source_end,speed`。来自本版实际真人/独立原声，源时间单位秒。
- `full_screen_visuals`: `id,from_frame,to_frame,purpose,action`。只列替代主画面的实拍/流程/演示，不把字幕/普通真人重点字算进。
- `pip_segments`: `id,asset_id,from_frame,to_frame,source_start,source_end,media_type:"video",shape:"circle",muted:true,bounds:{x,y,width,height}`。来自实际层与遮罩配置，不从计划复制后冒充；跨源切点须拆开。
- `caption_regions`: 同样整数帧范围和`bounds`。使用最终字幕实际布局（变布局时分段），用于与圆窗做保守矩形碰撞检查。
- `brand`: `status:"pending_logo"`或`"ready"`。ready包含实际`logo_path,logo_sha256,palette`（角色→#RRGGBB）、`palette_bindings`（`target,colors[]`，target覆盖keywords/cards/arrows/cover/ending）、`watermarks`（`id,from_frame,to_frame,opacity,preserve_aspect:true`）。范围外透明度需`contrast_adjustment`说明。

程序输出结构错误、待补Logo、PIP缺帧范围及不由程序证明的视听项，并绑定输入SHA256。缺Logo不会冒报品牌通过；静态头像、错误源时码、PIP缺帧、遮挡字幕、1.32错误速度、遗漏品牌组件/水印范围都应报错。未达到`ready_for_brand_delivery`时退出非零，但其他技术/剪辑工作可继续。

导出后还要实际查看开场、全屏效果每段头中尾、所有跨源边界、Logo在深浅背景、圆窗口型/裁切、字幕与状态；检查动画覆盖是否真正增加。程序检查源时码/形状字段不能证明实际圆形像素、人物身份或口型同步。连续全片观看、试听、人工200ms同步仍独立记录；未执行就未验证。

## 6. 交付与局部修改

固定MP4、TXT、SRT、独立封面及片内封面、完整制作说明和全片逐秒/逐帧表继续交付。品牌审计与实际成片哈希一起保存到该视频目录。后续换Logo/调淡、换颜色、移动圆窗或加动画只重做相关画面和QA；更改速度则重算所有受影响层与字幕，不重做有效ASR。保持旧输出、可编辑主轨、动画源码和三条声音。
