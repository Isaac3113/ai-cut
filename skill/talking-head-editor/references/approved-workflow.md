# 从首次沟通到认可成片：完整执行顺序

这是总 Skill 的工作流程和教学入口。完整质量规则在 [master-playbook](master-playbook.md)，当前视觉/声音预设在 [user-preferences](user-preferences.md)，动画细节在 [reference-motion](reference-motion.md)。无需把多个入口全部读进每一次局部修改。

## 已认可的标准及适用范围

2026-09-21音乐最终认可：用户认可AIVD4 R6并要求未来沿用。所有带配乐口播采用[user-preferences](user-preferences.md)的aivd4-r6-quiet-bgm-v1极轻标准，替代旧15～20LU起点及R4/R5音量；同片不重复衰减，新曲按实际响度/听感校准，SFX与人声保持独立。

2026-09-21工具路线澄清：本用户默认 ChatCut 为唯一主编辑时间轴、最终导出和在线手改入口；只有用户明确选择本机或剪映才切换。换电脑先核验当前工具、账号、本片projectId与活动timelineId，不能沿用旧“已安装”状态。缺少ChatCut能力时说明具体缺口，继续独立分析/素材准备；不能静默把整条本地MP4或ZIP当在线工程。下文“本机plan/revision”只用于明确选择的本机路线或辅助素材，不是随意替换主工程的选项。外部动画必须真实导入回ChatCut，人声/BGM/SFX独立，重点音效按事件保留独立可选片段。具体边界见[chatcut](chatcut.md)与[manual-editing](manual-editing.md)。

2026-09-19：用户明确认可001完整版，并指定以后有电脑实操的口播必须自动采用[practical-demo](practical-demo.md)的约3秒节奏、六类真实屏幕效果和同步轻音效；无实操时不强加。已认可风格不反复做样片批准，新片比例和内容仍独立确认/检查。001音乐相对样片降低30%是个案，不对每条重复执行；用户认可不冒充代理已连续视听。

2026-09-15工作流0.2.7：用户认可本条两平台文案、无AIDA标注/每三段空行/复制文本框，以及Facebook原封面和小红书3:4样稿。现又认可额外4:3横版小红书封面；之后完整片按[social-delivery](social-delivery.md)一次交付两篇文案、三张封面共五项；同一认可只复用风格，内容和图片逐片检查。

2026-09-13品牌与圆窗更新优先：每条默认绝对1.2倍；Logo颜色覆盖旧黄/奶油；淡Logo水印；全屏素材强制同源动态圆窗；按原话机制增加对象动作。执行与审计见[brand-and-presenter](brand-and-presenter.md)，旧案例数值不自动复制到新片。

2026-09-12，原创作者明确认可最后一版完整视频及 HyperFrames/Remotion 的做法，并要求以后沿用。该认可覆盖视觉风格、动画分工、重点字、画面节奏和声音呈现。对该创作者的后续教学口播，直接沿用本标准，不每条重新询问是否喜欢同一种样式。

这是风格反馈，不能补写为代理已经连续看完、听完或人工测量字幕同步。每条新视频仍有独立的内容、技术、许可和视听检查。公开使用者可明确选择本预设；案例认可不是其他人的个人批准、账号权限或素材授权。

| 7 | chatcut:asset-import → 主时间轴合成 | 导入真实渲染出的无声动画；添加人物/字幕及独立人声、BGM、逐事件SFX |

## 新视频的逐步工作方法

| 步骤 | 判断与操作 | 工具及实际产物 | 如何确认 |
|---|---|---|---|
| 01 接收 | 区分真人原片、可剪素材、文稿、纯风格参考；复用已提供路径，不重复问 | 主 Skill；任务简报、输入角色、源哈希 | 路径可读；参考片不会直接冒充可剪素材 |
| 02 检查 | 检查显示比例、旋转/SAR、帧率/PTS、音轨、颜色、可解码性与人物位置 | FFprobe/FFmpeg；源检查与抽帧 | 真实原片存在；损坏/隐私问题有记录 |
| 03 转写 | 原声为准；稿件纠正术语；数字、英文、否定、条件逐项核对 | 有效旧转写或 FunASR/已授权 ChatCut 转写；时间对应文本 | 没有识别的部分不编字词时间戳 |
| 04 粗剪 | 比较完整重录；删失败版本、无义口癖和离题；有意强调/条件/呼吸保留 | editorial、Script 或本机 plan；删除理由、独立原声粗剪 | 顺畅且可恢复；不先用动画掩盖吞字或意义错误 |
| 05 重排 | 从原片挑开场，以完整语义单元移动；检查指代、因果和前提 | 唯一主时间轴及源片映射 | 没有拼出原来没说的意思 |
| 06 定时 | 默认口播和原声1.2倍一次，指定速度则按原声绝对值；映射字幕/事件并计入封面；按本条用户已确认的视频比例布局 | ChatCut 当前活动时间轴或本机 revision | 外部动画/BGM保持1.0；禁止成片再整体加速 |
| 07 选材 | 每段先写“观众需要看到什么”；比较自有、免费和付费候选的相关性、画质、动作、构图 | 实际看录屏/视频片段；候选与来源许可表 | 不按文件名判断；无关或全黑素材不硬用；付费需真实批准 |
| 08 拆场景 | 先标实操有无与区间，有则启用6D；原话 → 对象 → 动作 → 条件 → 结果 → 引擎 → 起止帧；拆出能看懂的连续步骤 | 场景表、素材计划与主时间轴锚点 | 并列状态不用因果箭头；教学模拟标示意 |
| 09 动画 | 按上述6A/B/C及适用时6D选择；客户卡移动、消息出现、计时推进、结果高亮；留出阅读时间 | HTML/React/原生MG源码；进入/变化/停留/退出 | 实操约3秒并配同步音效；普通口播3～5秒有可见变化，不靠无意义抖动凑数 |
| 10 预检导入 | 固定依赖版本，先检查/渲染动画并实看，再官方导入 | run.ps1、引擎检查、MP4、素材ID、文件哈希 | 有真实文件，不只存在源码或素材池占位 |
| 11 合成 | 主画面、B-roll/流程、同源动态圆窗、Logo水印、重点字、字幕各有位置 | ChatCut 同一时间轴；原生层与外部素材记录 | 小窗显式静音，不挡标签；原声只播放一次 |
| 12 精修 | Logo品牌配色重点字、必要警示色、短词分拍弹入；人物轻推近/回位；常规字幕清楚 | 主 Skill + 原生MG + 模板；字幕/视觉事件表 | 重点层不是整段字幕；浅/深底都可读；手机大小检查 |
| 13 声音 | 单独把人声处理清楚，再混安静教学BGM与关键动作短SFX | A1人声/A2音乐/A3逐事件音效片段；音源/时码/增益及响度、试听记录 | 不在混合后整体提响度；按本条要求改BGM，保持人声；不能用完整混音替代逐个可改片段 |
| 14 片尾 | 约3秒，使用本条原片的真实头像和已授权结束语 | Remotion 片尾；来源与裁切 | 不继承讲师头像/品牌，不合成新身份或话语 |
| 15 封面 | 剪后TXT + 平台 + 已查看的本人帧 → 图片提示词员工结构稿 → 主员工审核优化 → 内置imagegen → 主时间轴 | 结构稿、执行Prompt、封面、源绑定与片内范围 | 本人/中文/事实/手机可读；首帧与边界实检，模型只按实际元数据报告 |
| 16 字幕导出 | 读取含封面/最终速度的全部字幕卡 → export_final_subtitles.py | 同源TXT/SRT及哈希清单 | TXT无时间/编号；SRT按最终帧，不能再次偏移或加速 |
| 17 导出验收 | 官方完整导出 → 全解码 → 看全片/听全片 → 全字幕及所有接缝、封面、动作/声音重点复核 | MP4、技术/视觉/听审分项报告 | 没看/没听/没测就标未验证；不能由测试数替代 |
| 18 说明交付 | 冻结证据生成逐段过程、全片逐秒/逐帧表；ChatCut路线核对浏览器可见时间轴与最终MP4，本机路线核对选定revision与输出 | 完整MP4、独立封面、TXT/SRT、完整制作说明、工程及记录 | 表格计算不冒充逐帧观看；不只交独立动画；所有交付绑定本版 |

## 一个场景的填写示例

以下是教学示例，不是下一条原片的事实或固定时间安排：

| 项目 | 示例 |
|---|---|
| 口播含义 | 尚未购买时，系统持续跟进并保留记录 |
| 对象与条件 | 同一个客户档案；当前状态“未购买” |
| 动作 | 客户卡入场 → 跟进记录逐条出现 → 时钟指针推进 → 高亮当前阶段 |
| 引擎与字幕 | Remotion 多步骤；字幕留在 ChatCut 主轨，句子来自真实原声 |
| 关键音效 | 只在首次记录/状态确认轻响；时钟不持续吵闹 |
| 帧绑定 | 主时间轴 startFrame + 素材局部帧；素材长度按本次口播重新算 |
| 检查 | 条件没被遮住；时钟是示意，不捏造响应速度；真人小窗只保留一份原声 |

素材记录保留引擎/版本、源代码、起止帧、渲染哈希、许可和检查；这些是执行记录，不能只新增字段就宣称能力完成。

## 从多轮反馈沉淀下来的规则

| 反馈 | 最后确定的做法 | 应避免的旧问题 |
|---|---|---|
| 去废话又要保留意思 | 先比较重录和完整语义，再做可恢复粗剪 | 机械删除所有“嗯/然后”，删掉否定/限定条件 |
| 不要默认两版 | 每条新片先确认视频比例，只做所选一版；明确要求才多版 | 默认为原比例，或把多封面当多版视频 |
| 要加快但自然 | 主体1.2倍一次；动画按最终帧制作 | 导出后再加速，使字幕和素材错位 |
| 文字假、画面没感觉 | 真实录屏/实拍或有对象动作的示意；短重点字辅助 | 几张纯文字卡代替流程 |
| 音乐反复调还太响 | 原声先处理；BGM/SFX独立；避免混合后再整体归一化 | 固定“5%”等同最终听感，或降低人声迁就配乐 |
| 视频沉闷 | 普通口播每3～5秒有效变化；有实操按约3秒真实屏幕重点变化并同步轻SFX | 无关抖动、过密大转场，或有实操却只做字幕变化 |
| 重点全白、流程死板 | 当前Logo品牌配色、粗重点短词、克制偏移阴影和分拍对象动作 | 复制历史黄/奶油案例配色，或只堆大字 |
| 想手动修改 | ChatCut原生主轨与独立人声/BGM/逐事件SFX；外部动画保留源码可重渲染 | 将MP4/ZIP称为在线工程，或将整条SFX混音称为逐个可改 |
| 动画没出现在正式视频 | 检查实际浏览器所选时间轴、最终MP4相同时间点，交付完整文件 | 只看后台activeTimelineId或只发单独素材 |
| 现在认可，以后同样做 | 对原创作者沿用该预设；公开读者可明确采用 | 继续写“未认可”，或把风格反馈当全片技术/听审全通过 |

## 剪辑交互更新0.2.8

每条新视频把[比例确认与原片1.2倍](user-preferences.md)作为剪辑之前的第0步：先问比例，回答后保存简报、按选定比例构图；未来速度一律以原始录音直接1.2倍一次为默认，不沿用历史1.44倍追加版本。用户本条已提供比例或同片局部修改无需重复问。封面三图与视频比例分开；其余制作顺序、工具分工和五项发布素材交付不变。
