# 每条完整短视频的固定交付

适用于新剪、完整重剪及输出完整新版本；不要求局部预览也制作一套全片资料。总 Skill 负责组织并实际生成本页产物。现有剪辑器仍是唯一主时间轴；不要为交付记录重建剪辑架构。

## 交付内容

每一条完整视频都同时给创作者：

1. 实际可播放 MP4，包含本条封面画面；保留原画幅，按要求才追加其他比例。
2. 独立封面 PNG 或 JPG，以及所用真实原片帧的来源绑定。
3. 与此版 MP4 一致的 SRT 和 TXT。TXT 只含完整剪后口播正文，没有时间轴、帧数、卡片编号、文件说明或工具记录。
4. 完整制作说明：从原片到这一版的实际步骤、逐段制作顺序、剪辑用途、字幕/特效/素材/声音/封面/片尾的具体处理及其证据。
5. 覆盖完整输出的逐秒表与逐帧表，或具有等价完整数据的查询页；正常真人区间也写明原片映射、基本剪切/速度/构图/字幕/声音处理，不能只登记有动画的时间点。
6. 当前可恢复工程或真实在线工程地址、素材来源/许可表、检查报告。受限素材不随意分发原件。

按新版本写入新目录，旧 MP4、SRT、TXT、封面和报告保留。短改生成了完整新视频时，同步更新依赖它的交付文件；不能把旧字幕或旧逐帧表配给新成片。

## 执行顺序

1. **锁定本版语义与速度。** 已有有效粗剪和转写直接复用。记录原片哈希、源片段、输出顺序和本次绝对口播速度。默认仍为 1.1 倍；2026-09-13 用户指定本条改成相对原声的 1.2 倍，不自动改为以后每条默认 1.2。
2. **重算唯一主时间轴。** 以原片源范围重新计算各段输出边界。旧版已为 1.1，改成 1.2 就是绝对设为 1.2，不能算成 1.1×1.2。同步移动视频、人声、字幕、素材锚点、重点字、SFX 和片尾；流程动画按新的时间区间重排/重渲染并保留阅读时间，BGM 保持自然速度。不能简单加速混合成片而让音乐和动画也被整体加速。
3. **先导出正文 TXT，制作封面。** 从当前剪后口播卡片生成不带时序信息的 TXT，提取并实际查看清晰、自然、与本人一致的一帧。将这份 TXT、平台及真实参考帧交给 [图片提示词员工](cover-prompt-worker.md)。平台未给时按本片显示比例制作通用视频封面，并记录平台适配未验证，不擅自追加多个比例。
4. **主员工审核 Prompt 后生图。** 对照原声核对主题/条件/标题，不添加未讲过的收益和承诺；校验本人身份、参考帧、画幅、中文和手机可读性。保存员工原稿、主员工采用的执行版及两者事实性变化。使用可用的内置 imagegen，并按其 Skill 实际读取参考图后生成；模型名称/版本只有工具元数据确实返回才报告，不把“最新、最强”写成已证明的模型名。
5. **把封面放入视频。** 保留独立图片并作为真实素材加入主时间轴，登记起止帧。无另行要求时用约 1 秒开场封面，完整口播从封面后开始；轻声 BGM 可衔接，封面不重复生成新口播。封面文字不混入“实际口播” TXT 或 SRT。若采用开场原声上的短叠图，须检查不遮本人/已有字，并按实际记录，不能既占位又重复偏移。
6. **重新冻结最终字幕。** 插入封面/改速度之后重新从主时间轴读出全部字幕，保存卡片 ID、最终起止帧和文字。最终 SRT、TXT、烧录字幕共用这一份；核对它与第 3 步正文无语义变化，有变化则重新核对封面主题。不要把旧导出 SRT 当成当前权威文本。
7. **导出、实检、记录。** 检查真实 MP4 的封面首帧/结束边界、正文第一句、所有接缝/动作/字幕、声音及尾帧；完整解码、完整观看/试听及人工同步各自记录，未执行明确未验证。封面图片生成成功并不证明已出现在视频里。
8. **由冻结证据生成说明。** 使用导出绑定的快照、素材哈希、实际源码和输出视频，完成下列说明与覆盖表，然后把完整交付链接一起给用户。

## 完整制作说明如何写

说明这一版最终采用的制作方案，不混入用户未要求的返工历史。可保留历史在内部日志；不能伪称现在的源码或 Skill 已经在旧导出中执行。

- **版本依据：** 输出文件/哈希、revision 或 timelineId/renderId、显示尺寸、fps、视频帧数、正文速度、封面及片尾长度。区分视频末帧与编码音频尾巴。
- **从头到尾：** 接收原片、检查、转写/复用、粗剪/重排、定时、选素材、拆场景、生成动画、合成、字幕、声音、封面、导出和验收。每步写实际调用、产物、完成状态；未调用的 Skill 只能写“对应职责/可用规则”，不能标为已执行。
- **每个段落：** 原话/保留条件、源入出点、输出区间、采用画面、按序的制作动作、事实支持的剪辑用途。说明“让观众看懂状态变化”等可审查的设计理由，不杜撰当时的完整思考过程。
- **字幕：** 原声/转写来源、词句核对、删改/重排/加速/封面偏移如何映射、断句、字体/字号/颜色/布局、原生或烘焙、SRT 与 TXT 的来源一致性。封面/流程内文字与口播字幕分开。
- **每个资产与效果：** 源文件或素材 ID、来源/作者/许可、使用范围、作用、实际引擎/版本/参数、入场/动作/停留/退出区间。普通真人区间说明无额外动画，以及仍存在的基础处理。
- **声音：** 原声/BGM/SFX 分轨来源、绝对速度、增益、淡入淡出、动作锚点、最终测量和听审状态；音乐文件已预处理时说明 0dB 代表保持什么基准。
- **封面：** 来源原片时间/帧和哈希、平台/比例、TXT 输入、标题选择及审核后的执行 Prompt、生成工具元数据（若有）、独立文件、主时间轴范围与实际成片抽帧证据。
- **限制：** 工具执行证据与说明性重建分开；未知参数、未看、未听、未测都显式标明。逐帧 CSV 是工程计算结果，不能把生成 3000 行等同逐帧人工观看。

覆盖表每行至少包含输出帧或秒区间、原片时间映射、段落/剪切、活跃素材与效果、字幕/重点字、原声/BGM/SFX、工具/Skill证据。外部动画注明局部帧与实际动作阶段。帧范围统一 `[start_frame, end_frame)`；帧表应恰好覆盖 `0 .. video_frame_count-1`，秒表末行按实际余数截止。无源画面的封面/片尾不捏造原片时间，只有肖像来源另列。

总 Skill 应结合真实工程完成这些表；`export_final_subtitles.py` 只负责字幕导出与结构校验，**尚不是通用逐帧视频审阅或完整报告生成器**。每次仍需实际创建说明和覆盖数据并检查。

## 可重复执行的字幕导出

源码工具：`scripts/export_final_subtitles.py`（相对 `TALKING_HEAD_EDITOR_ROOT`）。无需付费 API；按绝对帧边界用有理数 fps 转为毫秒，避免逐段四舍五入漂移。

输入 UTF-8 JSON 数组，文字必须来自本版真实口播字幕，示例仅说明格式：

```json
[
  {"id": "c1", "start_frame": 30, "end_frame": 95, "text": "客户在哪一步？"},
  {"id": "c2", "start_frame": 95, "end_frame": 140, "text": "可以看到状态。"}
]
```

```text
python scripts/export_final_subtitles.py --cards final-cards.json --fps 30 --duration-frames 170 --output-stem NEW_OUTPUT/字幕
```

- 输出 `字幕.srt`、`字幕.txt`、`字幕.subtitles.json`。TXT 没有标题或技术字段，默认每卡一行；如需正文自然分段，用 `--paragraphs paragraphs.json`，内容为按原顺序完整分组的 ID 数组，如 `[["c1","c2"]]`。只改变空白，不重写词句。
- 输入已经包含封面时不加偏移。只有输入明确尚未偏移才传 `--offset-frames 30` 等实际值；输出清单记录这次偏移。工具不自动加速，也不猜封面时长。
- 校验唯一 ID、非空文本、整数帧、起止顺序、无重叠、毫秒有效时长、最终片长、分组不漏字/不重排。失败不静默删除或合并卡片，先回主时间轴核对。
- 输出保留输入哈希、最终边界、fps、文件哈希和未验证项。拒绝覆盖已有路径。清单通过只是结构通过，仍须用本版实际 MP4 复核字幕内容及同步。

在最终交付前实际核对：SRT 与 TXT 去除排版空白后的文字序列相同；封面及片尾无口播时不新增字幕；首尾字幕边界落在本版视频内；报告、覆盖表、SRT 与 MP4 指向同一个版本。测试不代替实际听审。

## 已认可动画的调速复用

新制作动画优先按最终时间生成并以1.0倍插入。只调整已认可成片的口播速度时，可以复用已认可的完整动画文件，明确设置“原动画完整帧数 ÷ 新占用帧数”的播放率，同步原声、字幕、动作和阅读停留；必须在交付表登记局部时间映射并检查实际输出。不把这种复用说成重新运行了Remotion或HyperFrames，也不再次整体加速混合MP4。片尾与BGM可保持1.0倍；无法安全读完的动画应回源码重排。
