# 剪映口播工程适配

这是现成开源 Skill 的本地适配入口。上游固定为 `luoluoluo22/jianying-editor-skill@32c56928ded4f9e2c2b80e099dc7abb793d2c30b`，原入口保存在 `UPSTREAM_SKILL.md`，MIT 与 vendored pyJianYingDraft 的 Apache 2.0 许可保留。不要把上游描述的版本范围当成本机兼容证据。

真人口播继续由 `talking-head-editor` 管理内容、许可、删改和时间轴。先读其 `references/jianying.md` 与当前项目验收记录。源码位于 `C:\Codex Workspace\AI-Talking-Head-Editor`，入口与参数以该项目实际脚本和 `--help` 为准。

## 本地执行范围

- 用已审核的 vendored 核心类生成文件；构建时不导入上游 Windows UI 控制器和 `DraftFolder`，不执行 `JyProject(...overwrite=True)` 的覆盖/修复逻辑。
- 只生成全新工程。向剪映写入前必须确认是本任务创建的独立草稿，备份原文件并比较哈希，退出该工程的编辑界面。不要修改其他草稿或写正在编辑的工程。
- 基于本机真实空白模板保留版本字段，不能通过改低版本号或关闭兼容门禁来宣称成功。加密文件保持原样；不默认解密，不更换或降级用户的软件。
- 主视频、字幕、关键词、素材与人声/BGM/SFX分轨。已处理得很轻的音乐轨默认100%就是当前轻声基准，50%可以继续减半；不开启自动响度，不重复叠加原片音轨。
- 不因上游示例启用TTS、上传私有原片、购买音乐或运行云素材服务。用户已有的真实原声和明确许可的素材优先按主规则处理。
- 上游所谓“无头导出”实际依赖Windows窗口操作。此环境使用 Computer Use 的真实窗口工具验证，不同时运行另一套UI自动化。

## 用户同时使用电脑

后台建工程、字幕及素材文件不占鼠标键盘。操作剪映窗口会用到同一会话的焦点；检测到用户输入或窗口状态失效时重新观察，不反复抢焦点。需要用户恢复窗口时说明具体工具错误，并继续不依赖窗口的后台工作。

Codex右侧可展示制作记录和媒体预览，不能冒充已嵌入剪映时间轴。用户手动改音乐、字幕与片段应在真正的剪映工程里操作。

## 验收与交付

依次记录：文件构建和结构检查、剪映内打开、独立轨道手调、原生MP4导出、导出文件完整解码和画面检查、实际观看/试听。没有执行就标未验证。

素材视频内部已经渲染好的流程或头像文字不能称作原生可编辑文字；它们可作为独立素材替换/裁剪。原生字幕与关键词须分别验证。只生成草稿或FFmpeg预览时，不说“已用剪映完成成片”。
